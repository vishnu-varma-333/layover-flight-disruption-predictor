# Layover — Flight Disruption Predictor

Layover is a real-time system that warns travelers they will miss a
connection before the airline says so, by tracking the physical aircraft
behind each flight instead of trusting the schedule alone.

Full design, data sources, architecture, tech-stack rationale, data model,
and milestone plan live in [`docs/MILESTONES.md`](docs/MILESTONES.md) and
[`DECISIONS.md`](DECISIONS.md). A recruiter-facing narrative with the
headline results is in [`WRITEUP.md`](WRITEUP.md); the model's accuracy,
calibration and known limitations are in
[`docs/MODEL_CARD.md`](docs/MODEL_CARD.md).

## Local development

Requires Docker, Python 3.9+, and Node.js 20+ (for the web app).

PyFlink (Milestone 6) additionally needs a local JVM (Java 17+) and a
Kafka connector JAR, neither installed via Homebrew — see
`make rotation-job` below and DECISIONS.md for the exact setup
(`~/.local/jdk`, `~/.local/flink-connectors`).

```bash
make up          # start Kafka (Redpanda), TimescaleDB, Redis, OTel/Prometheus/Grafana
make verify      # run live health + round-trip checks against every service
make down        # tear down

make fetch-data  # download BTS On-Time Performance data + airport reference (resumable)
make build-data  # clean raw data into Parquet; build aircraft rotations
make verify-data # live DuckDB data-quality checks against the processed Parquet

make train-model # build features + train/evaluate the LightGBM delay models, log to MLflow
make backtest    # replay a real month through Kafka, scoring with the trained models live

make live-ingest # run the real OpenSky/NOAA/FAA ingestors (Ctrl-C to stop, or pass --duration)
make verify-live # live checks against events already published to live.events

make rotation-produce # build a real day's messy event stream + ground truth, publish to Kafka
make rotation-job     # run the real PyFlink rotation-linking job (bounded: stops once caught up)
make rotation-verify  # compare the Flink job's real output against ground truth

make sync-features    # sync the Flink job's output into Redis (the online feature store)
make predict-service  # run the FastAPI prediction service (GET /flights/{flight_id}/risk)
make verify-predict   # live checks + a cross-check against the real running service

make trip-schema             # apply the trips/trip_legs/alerts/risk_assessments schema
make trip-worker              # run the real Temporal worker (workflows + activities)
make trip-start                # create a real trip and start its monitoring workflow
make verify-trip-monitoring    # the full live kill test (SIGKILLs and restarts a worker)

make web-api      # run the internal API the web app talks to server-side (port 8001)
make web          # run the Next.js web app (port 3001; run `npm install` in web/ first)

make test        # unit tests
make lint        # ruff
```

The web app (`web/`) is a separate Node.js project — `cd web && npm install`
once, then `make web` from the repo root. It needs `make web-api` and
`make predict-service` running too (and a Temporal worker, `make
trip-worker`, for live risk to update).

### Containers and AWS (Milestone 10)

Every always-on service is containerized (`Dockerfile`, `web/Dockerfile`):

```bash
docker compose -p layover -f infra/docker-compose.yml -f infra/docker-compose.prod.yml up -d --build
```

`infra/terraform/` provisions one EC2 host, S3, Secrets Manager and
least-privilege IAM for a real deployment — written and
`terraform validate`-clean, **not applied** (no AWS account available in
this environment; see `DECISIONS.md`). `docs/RUNBOOK.md` covers
operating the stack and recovering from common failures.

## Repository layout

```

scripts/    operational and verification scripts
src/        installable packages (layover_data: historical-data ETL; layover_model: features + training;
            layover_backtest: Kafka replay harness; layover_ingest: live OpenSky/NOAA/FAA ingestors;
            layover_stream: PyFlink rotation-linking job; layover_predict: FastAPI prediction service;
            layover_trip: Temporal trip-monitoring workflow + alerting; layover_web: the web app's
            internal backend API)
web/        the Next.js PWA (TypeScript) -- a separate Node.js project
data/       raw downloads + processed Parquet (gitignored, regenerated by scripts/)
docs/       milestone tracking, benchmarks, model card, replay report, runbook, postmortem, demo script
DECISIONS.md   design-decision log
WRITEUP.md     recruiter-facing project narrative
```
